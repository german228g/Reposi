# Business Launch AI — Telegram-бот для запуска бизнеса

Пользователь описывает идею → бот понимает нишу, задаёт только нужные вопросы, собирает бренд
(название, слоган, лого, палитра, посты, план на 7 дней) и **сам создаёт Telegram-канал**:
ставит аватарку, описание и публикует посты от имени подключённого аккаунта.

## Что внутри

- **Обученный классификатор ниш** — 21 ниша, Naive Bayes на словах, биграммах, символьных
  триграммах и префиксах. Точность **92.6%** на отложенной выборке, **100%** на контрольных фразах.
- **Гибридное распознавание** — модель + точные многословные фразы («туры в горы», «чехлы для телефонов»).
- **NLU** — из текста вытаскиваются город (с падежами), возраст аудитории, бюджет, модель бизнеса,
  продукт. Бот не переспрашивает то, что уже сказано.
- **MTProto (Telethon)** — реальное подключение Telegram-аккаунта: создание канала, аватар,
  описание, публикация постов, добавление бота админом.
- **Генераторы** — логотип PNG/SVG под стиль и палитру ниши, 7 постов, бренд-пакет в Markdown.

## Быстрый старт

```bash
cd business-bot
cp .env.example .env          # впиши TELEGRAM_BOT_TOKEN
chmod +x run.sh
./run.sh                      # обучит модель и запустит бота
```

Вручную:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/train_ai.py --rounds 3 --per-keyword 10
python -m bot.main
```

## Обучение

```bash
python scripts/train_ai.py --per-keyword 12
```

Скрипт:

1. генерирует сбалансированный корпус бизнес-идей на RU/UA по всем нишам
2. обучает классификатор (train/test split)
3. считает точность общую и по каждой нише
4. проверяет 35 контрольных фраз так же, как это делает бот
5. пишет `knowledge/model.json`, `trained.json`, `train_report.json` и `finetune_dataset.jsonl`

Скрипт завершается с кодом 2, если контрольная точность упала ниже 85% — удобно для CI.

Отчёт последнего обучения лежит в `bot/ai/knowledge/train_report.json`.

## Реальное создание канала (MTProto)

Bot API не умеет создавать каналы, поэтому используется MTProto.

### Настройка владельцем — один раз на весь сервис

`api_id` и `api_hash` принадлежат **приложению**, а не пользователю. Один комплект
обслуживает всех клиентов, поэтому клиенты этих ключей никогда не видят.

1. Открой [my.telegram.org](https://my.telegram.org) → **API development tools**
2. Создай приложение, скопируй `api_id` и `api_hash`
3. Пришли боту (доступно только `ADMIN_USER_IDS`):

```
/setapi 1234567 0123456789abcdef0123456789abcdef
```

Бот проверит ключи, сохранит в `.env` и удалит сообщение с ключами из чата.
Перезапуск не нужен. Альтернатива — вписать `TG_API_ID` / `TG_API_HASH` в `.env` руками.

### Что делает клиент (один телефон)

1. **Подключить аккаунт**
2. присылает номер: `+380971234567`
3. получает код (по SMS, если Telegram дал, иначе в чате «Telegram»)
4. присылает код **через тире**: `2-9-2-1-8` (не `29218`!)
5. если есть 2FA — присылает облачный пароль
6. дальше рассказывает идею

После сборки бренда бот сам создаёт канал, ставит лого аватаркой, пишет описание,
публикует посты, добавляет себя администратором и присылает ссылку-приглашение.

### Почему код через тире

Telegram аннулирует код, если его прислали в чат сплошняком (`29218`) —
защита от фишинга: «вход заблокирован, поскольку ранее Вы сообщили этот код».
Разбитый формат (`2-9-2-1-8` / `2 9 2 1 8` / `a29218`) тот же код, но антифишинг
его не срабатывает. Сплошной код бот даже не отправляет в API — сразу просит тире.

QR остаётся запасной кнопкой для тех, у кого есть второй экран.

Пока ключи не настроены, клиент видит нейтральное «подключение временно недоступно»
и работает в режиме помощника; техническую инструкцию видит только владелец.

Сессии хранятся в `data/sessions/<user_id>.session` с правами `600`, отключение — `/logout`.

## Команды

```
/start          меню
/connect        подключить Telegram-аккаунт (номер → код через тире)
/new            новый запуск бизнеса
/createchannel  создать канал автоматически
/brand          пересобрать бренд и лого
/posts          показать посты
/status         статус
/logout         отключить аккаунт
/setapi         ключи приложения — только владелец сервиса
```

## Опционально: LLM для свободных ответов

- `GROQ_API_KEY` — бесплатный API [Groq](https://console.groq.com)
- `OLLAMA_BASE_URL=http://localhost:11434` — локальная модель

Без них бот отвечает на обученной базе знаний по нише.

## Структура

```
business-bot/
  bot/
    main.py                 запуск, таймауты, rate limiter
    handlers.py             флоу: аккаунт → опрос → бренд → канал
    config.py               ключи приложения и админы, запись в .env
    telegram_account.py     MTProto: вход по номеру/SMS/QR, создание канала, посты
    logo_generator.py       лого PNG/SVG
    posts_generator.py      посты и бренд-пакет
    ai/
      engine.py             гибридное распознавание + генерация бренда
      classifier.py         Naive Bayes
      corpus.py             генератор корпуса
      nlu.py                гео, возраст, бюджет, продукт
      domains.py            21 ниша: советы, палитры, лексика
      knowledge/            model.json, trained.json, train_report.json
  scripts/train_ai.py       обучение с метриками
  data/                     профили, бренд-пакеты, сессии
```

## Безопасность

- `.env`, `data/users`, `data/brands`, `data/sessions` не попадают в git
- Токен бота и api_hash не логируются
- Если токен где-то светился — перевыпусти через `/revoke` в @BotFather
